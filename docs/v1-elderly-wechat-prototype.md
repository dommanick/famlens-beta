# V1 Product Prototype: WeChat Grocery Helper for 50+ Chinese Parents

## Product Thesis

海外 50+ 华人父母在超市买东西时，真正困难的不是“英文翻译成中文”，而是：

- 看不懂这个商品到底是什么。
- 不知道买回家怎么用。
- 不知道是不是容易买错。
- 不知道能不能做成自己熟悉的饭菜。
- 不方便现场问子女，或者问了也要等回复。

V1 要做的是一个微信里的“商品解释和使用助手”，不是健康管理 App，也不是通用翻译工具。

## Target User

第一版只服务一个窄人群：

在美国/加拿大生活的 50+ 华人父母，英文弱，日常主要用微信，购物地点包括 Costco、Walmart、Trader Joe's、华人超市、Safeway、Kroger 等。

典型特征：

- 不愿意安装新 App。
- 微信使用熟练，尤其熟悉拍照和语音。
- 阅读长文字有压力。
- 视力可能不好。
- 对 AI 没兴趣，只想知道“这个能不能买、怎么吃”。
- 中文也不适合太书面，需要口语化、短句、明确结论。

## Core Promise

一句话定位：

> 在国外超市看不懂商品，拍给我，我直接告诉你这是什么、能不能买、怎么吃。

用户心智：

不是“翻译”，而是“像懂超市的家人一样解释给我听”。

## V1 Scope

### Must Have

1. 用户发商品照片。
2. 用户发语音问题。
3. 机器人用极简中文回复。
4. 生成一张大字图文卡片。
5. 对重点结论生成一段短语音。
6. 回答固定为“结论优先”。
7. 回答里主动提示是否需要补拍：配料表、营养表、烹饪说明、条码。
8. 支持自由追问，但自由追问不是主入口。

### Should Have

1. 常见品类识别：
   - 奶制品
   - 肉类部位
   - 冷冻食品
   - 调料酱料
   - 烘焙材料
   - 早餐食品
   - 儿童零食
   - 保健/营养品
   - 日用品/清洁用品
2. 常见避坑：
   - 看起来像牛奶但不是牛奶
   - 看起来像酸奶但含糖很高
   - baking soda / baking powder
   - heavy cream / half and half / sour cream / cream cheese
   - broth / stock / soup base
   - 不同牛肉部位
   - 调味半成品 vs 生食材
3. 用华人家庭语境解释：
   - 能不能炒
   - 能不能炖
   - 能不能煲汤
   - 能不能给孩子早餐吃
   - 能不能替代中国食材

### Not in V1

1. 不做完整 App。
2. 不做复杂家庭健康档案。
3. 不做购物车。
4. 不做比价。
5. 不做菜谱社区。
6. 不做全球多语言。
7. 不做医疗判断。

家庭健康信息可以作为“用户主动说了就记住”的增强能力，但不是 V1 主流程。

## Interaction Principles

### 1. One Shot First

用户发一张图后，机器人必须直接给答案，不要先问一堆问题。

错误体验：

```text
请问你想了解配料、做法、营养还是价格？
```

正确体验：

```text
这个可以买，但更适合偶尔吃。

它是调味好的冷冻鸡肉条，不是生鸡肉。
买回家主要是加热后直接吃。
```

### 2. Conclusion First

每次回复第一行必须是结论。

结论类型：

- 可以买
- 不太建议买
- 看情况
- 我不确定，需要再拍一张
- 这个容易买错

### 3. Short Sentences

每句不超过 20 个汉字左右。

少用抽象词：

- 不说“该产品适用于多种烹饪场景”
- 改成“可以炒，也可以夹面包”

### 4. Large Text Friendly

微信文字应分段清楚。

不要长段落。

每次回复控制在 120-220 个汉字，除非用户追问。

### 5. Voice as Summary

文字回答给细节，语音只说重点。

语音长度控制在 15-25 秒。

语音脚本示例：

```text
这个是调味好的冷冻鸡肉条，可以买。回家用空气炸锅或烤箱加热就能吃。它不是生鸡肉，不适合炖汤。盐可能偏高，不要天天吃。
```

### 6. Visual Card as Main Output

对 50+ 用户来说，图文卡片比纯文字更容易理解和转发。

每次商品分析后，默认输出：

1. 微信文字。
2. 一张大字图文卡片。
3. 一段短语音总结。

图文卡片不是营销海报，而是“购物判断卡”。

卡片目标：

- 一眼看到能不能买。
- 一眼知道这是什么。
- 一眼知道怎么吃。
- 一眼看到最大注意点。

### 7. Promptless UX

老人不应该学习怎么问 AI。

机器人要主动提供 80% 常见答案：

- 这是什么
- 能不能买
- 怎么吃
- 怎么做
- 容易买错什么

剩下 20% 用自由问答解决：

- “能给孩子吃吗？”
- “能炒菜吗？”
- “这个和牛奶一样吗？”

## Main User Flow

### Flow A: User Sends Product Photo

User:

```text
[图片]
```

Bot text reply:

```text
可以先买一小份试试。

这是半成品调味鸡肉。
不是生鸡肉。
回家加热就能吃。

适合：
夹面包、卷饼、配米饭。

做法：
用空气炸锅或烤箱加热。
再炒青椒、洋葱也可以。

注意：
这类通常盐比较高。
不要天天吃。

如果想看健康不健康，
再拍一张营养表给我。
```

Bot voice reply:

```text
这个是调味好的冷冻鸡肉，可以买一小份。回家加热就能吃，不适合炖汤。盐可能偏高，不要天天吃。
```

Bot visual card:

```text
┌────────────────────┐
│ 可以买一小份试试       │
│                        │
│ 这是什么：             │
│ 调味好的冷冻鸡肉        │
│ 不是生鸡肉             │
│                        │
│ 怎么吃：               │
│ 烤箱/空气炸锅加热       │
│ 可以夹面包、配米饭      │
│                        │
│ 注意：                 │
│ 盐可能偏高             │
│ 不要天天吃             │
└────────────────────┘
```

### Flow B: Product Is Unclear

Bot:

```text
我现在不太确定。

这张图只看到正面。
看不清配料和用法。

请再拍一张：
包装背面，或者烹饪说明。

我可以帮你看：
它怎么吃、要不要加热、
适不适合老人和孩子。
```

### Flow C: User Sends Voice

User voice:

```text
这个是不是牛奶啊？可以直接喝吗？
```

Bot:

```text
它不是普通牛奶。

这是 half and half。
中文可以理解成：
牛奶加奶油。

一般放咖啡里。
也可以做奶油汤。

不建议当牛奶大杯喝。
脂肪比普通牛奶高。
```

Bot voice:

```text
这个不是普通牛奶，是放咖啡里的半奶油。可以少量用，不建议当牛奶直接喝很多。
```

### Flow D: User Asks How to Cook

User:

```text
这个怎么做？
```

Bot:

```text
这个适合简单做。

做法一：
切块，加青椒洋葱炒。
最后配米饭。

做法二：
加热后夹面包。
放生菜、黄瓜、番茄。

不要长时间炖。
它已经调过味，
炖久了会太咸。
```

## Response Template

V1 默认文本模板：

```text
{一句话结论}

这是：
{用生活语言解释商品}

怎么用：
{直接吃/加热/炒/炖/烤/保存}

适合做：
{2-3 个常见用途}

注意：
{最重要的 1-2 个避坑}

看不清的话：
{需要补拍什么}
```

如果用户是老人，不用表格。

不要输出复杂营养术语，除非图片里明确出现。

## Visual Card Template

图文卡片尺寸优先适配微信聊天内查看。

建议比例：

- 竖版 4:5 或 3:4。
- 背景浅色。
- 字体大。
- 信息块不超过 4 个。
- 不放复杂表格。
- 不放小字免责声明。

默认卡片结构：

```text
顶部：结论
中部：这是什么
中部：怎么吃
底部：注意/避坑
```

### Card Copy Rules

标题必须非常直接：

- 可以买
- 不太建议
- 先别买
- 看情况
- 需要再拍背面
- 这个容易买错

每个模块最多 2 行。

不要使用：

- 营养成分复杂列表
- 长段解释
- 多颜色风险等级
- 小图标堆叠
- 医疗化判断

### Card Examples

#### Example 1: Half and Half

```text
标题：
不是普通牛奶

这是什么：
牛奶加奶油
常放咖啡里

怎么用：
少量倒咖啡
也能做奶油汤

注意：
脂肪比牛奶高
别当牛奶大杯喝
```

#### Example 2: Baking Powder

```text
标题：
这是泡打粉

这是什么：
做蛋糕发面的
不是小苏打

怎么用：
按食谱少量放
不能随便多加

注意：
买烘焙材料时
别和小苏打买错
```

#### Example 3: Unknown Product

```text
标题：
先别急着买

我看不清：
配料表和用法

请再拍：
包装背面
或烹饪说明

我再帮你看：
怎么吃
适不适合买
```

## First Screen Mental Model

如果未来做成 H5 或小程序，第一屏也只保留三个大按钮：

```text
拍商品
按住说话
看历史
```

但 V1 先不做小程序。微信聊天就是主界面。

## Voice Design

### Incoming Voice

用户可以直接问：

- “这个能不能买？”
- “这个怎么吃？”
- “这个是不是牛奶？”
- “这个能给孩子吃吗？”
- “这个能不能炒菜？”

系统需要：

1. 语音转文字。
2. 结合最近一张图片理解问题。
3. 用文字回复。
4. 生成短语音总结。

### Outgoing Voice

不要把全文读出来。

只读：

- 结论
- 是什么
- 怎么吃
- 最大注意点

## Output Priority

默认输出顺序：

1. 图文卡片
2. 短文字解释
3. 语音摘要

如果微信接口或开发成本限制导致不能一次都发，V1 优先级是：

1. 短文字解释
2. 图文卡片
3. 语音摘要

但从用户体验目标看，最终应该让图文卡片成为主输出。

## Conversation Memory

V1 只需要非常短的上下文：

- 最近一张商品图
- 最近一次商品分析
- 用户最近一次追问

不需要复杂长期记忆。

家庭健康信息只做轻提示：

```text
如果家里有人高血压、糖尿病、过敏，
你可以告诉我。
我下次会一起提醒。
```

## Product Personality

语气像耐心的家人。

不要像医生。
不要像客服。
不要像百科。

示例风格：

```text
这个可以吃，但别天天吃。
```

```text
这个不是你想的那种牛奶。
```

```text
这个适合炒，不适合煲汤。
```

```text
先别急着买，再拍一下背面。
```

## V1 Success Criteria

14 天内看这些指标：

1. 50 个种子用户里，是否有 20 人以上发过 3 次商品图。
2. 是否有用户在超市现场连续发多张图。
3. 是否出现自然追问：
   - “怎么做？”
   - “能给孩子吃吗？”
   - “这个和上次那个有什么区别？”
4. 是否有人把机器人推荐给父母或朋友。
5. 是否有人说：
   - “这个比翻译有用”
   - “我妈能看懂”
   - “我下次买菜还会用”

不要用“用户说喜欢”作为核心指标。

核心指标是重复使用和现场决策。

## V1 Build Order

1. 图片输入，返回极简商品解释。
2. 固定回复模板优化到老人能看懂。
3. 生成大字图文卡片。
4. 支持语音输入。
5. 支持语音摘要输出。
6. 保存最近一张图，支持追问。
7. 记录用户反馈：
   - 买了
   - 没买
   - 有用
   - 不准
   - 看不懂
8. 再考虑家庭健康偏好。

## The Product We Are Not Building Yet

不是：

- AI 翻译相机
- 健康评分 App
- 营养师 App
- 菜谱 App
- 购物比价工具

是：

> 给海外华人父母用的微信超市助手。
> 拍一下，告诉你这是什么，怎么买，怎么吃。
