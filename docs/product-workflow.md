# 产品原型与发布工作流程

更新时间：2026-06-21

## 为什么要改流程

FamLens 还处在产品定位、首页表达和核心体验快速调整阶段。首页 UI、功能入口、结果样式和增长表达不能一有想法就直接改代码，否则会造成重复开发、重复部署和理解偏差。

之后涉及首页、关键 UI、产品结构、用户路径、付费/增长入口等变更时，默认先讨论原型，再开发。

## 标准流程

### 1. 先做产品原型图

在开发前，先输出手机端原型截图或可视化设计稿。

要求：

- 必须是手机版，不只给桌面版。
- 必须展示完整页面，不只展示第一屏。
- 如果首页需要三屏滚动，就给三张完整连续截图。
- 需要把关键状态一起展示：未扫码、扫码后商品结果、扫码后小票结果、AI 追问、家庭设置等。
- 原型阶段允许快速调整文案、布局、入口和信息层级，不急着写正式代码。

### 2. 用户确认后再做本地开发

只有当原型方向确认后，才进入本地代码开发。

本地开发要求：

- 保持变更集中，不为每个小意见单独部署。
- 本地完成后先跑测试。
- 本地用手机视口截图做视觉检查。
- 本地功能至少验证：拍商品、拍小票、语言切换、AI 对话、家庭设置、结果示例隐藏逻辑。

### 3. 本地确认后再上传服务器

本地确认没有明显体验问题后，再部署到线上。

部署前检查：

- 静态资源版本号已更新，避免手机缓存旧页面。
- 不包含“测试版、内测、请测试”等内部运营文案。
- 首页定位、核心按钮、结果示例和实际结果页一致。
- 手机端能正常打开、拍照/上传、查看结果。

### 4. 线上发布后做 final check

部署后必须做最后一次线上检查。

检查内容：

- 打开正式域名。
- 手机端首页是否是本次确认版本。
- 产品图片和小票图片各测一次。
- 语言切换是否同步页面、结果、语音和 AI 文案。
- 家庭设置入口是否可见。
- 没有旧缓存、旧 UI、乱码或断裂布局。

## 默认工作约定

- UI 和首页类需求：先出原型图，不直接改代码。
- 小 bug、明确修复、文案错字：可以直接本地修。
- 线上部署：除非用户明确说“部署/上线”，否则先停在本地确认。
- 多个小改动：先集中整理，再一次性本地开发和验证。
- 给用户看设计稿时，优先提供图片截图，不只给 HTML 文件或链接。

## 当前产品方向提醒

FamLens 当前不是通用翻译器，也不是纯健康管理 App。

当前聚焦：

- 面向海外移民家庭。
- 解决海外购物看不懂、不会用、怕买错的问题。
- 通过商品和小票记录沉淀家庭购物记忆。
- 未来可发展出家庭购物顾问、健康饮食信号、消费结构分析和 ToB 商业合作。
